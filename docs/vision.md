## 1. 一句话愿景

让 SLAM 不只是被动测量,而是带着**世界模型(物理规律 + 几何规律 + 语义先验)**去**推理更合理的地图**:
墙应该平整垂直、桌子应该落地不悬空、玻璃会骗过 LiDAR——这些知识参与建图,而不是事后擦屁股。

形式化:把建图写成 MAP 优化

```
地图* = argmin( E_sensor + λ1·E_geometry + λ2·E_semantic + λ3·E_physics )
```

- `E_sensor`  传统 SLAM 的观测误差(重投影 / 点云配准)
- `E_geometry` 平面性、垂直性、尺寸范围约束(RANSAC 平面拟合、参数化模型)
- `E_semantic` 语义拓扑一致性(墙连通、地面不悬空、房间闭合)——**落脚点是场景图的节点与边**
- `E_physics`  重力、碰撞、不可穿透(物理引擎当验证器)

## 4. 数据架构原则(本文对当下唯一有约束力的部分)

**双层数据,永不混置:**

```
游戏世界层  .vxw chunks(4字节/体素:material/semantic/state/color)
            给渲染器和玩法看的"成品世界"。核心契约,轻易不动。
建图工作层  体积层 sidecar(规划中,SP-B 落地):{occupancy_weight, esdf_dist, parent, flags}
            建图算法的"草稿纸"。存自由空间、置信度、距离场。独立文件,独立演进。
```

这是 Hydra 的同款分层(Voxblox 体积层 vs DSG 场景图),也是本工程 §0 SoC 原则的直接推论。

### 4.1 已决事项(2026-06-13,经讨论定论)

| 提案 | 决定 | 理由 |
|---|---|---|
| 核心记录加 `is_surface` 标志 | **不加** | 表面性可在渲染期 O(1) 推导(查 6 邻居);greedy mesher 已只生成"占据↔空气"边界面(40 万体素 → 24.6 万三角即证据)。存它反而引入一致性负担:每次编辑都要级联更新邻居的 surface 位 |
| 核心记录加占据概率,扩 8 字节 | **不进核心记录** | 概率服务于多帧融合/去噪(建图工作层职责),渲染器不消费它。扩记录 = spec §4 破约 + 三处实现 + 全部测试 + 存量世界迁移,代价远超收益 |
| 概率/weight/esdf 放哪 | **体积层 sidecar(SP-B 设计)** | 工作态数据;补回放弃 TSDF 后丢失的"观测/未知"区分 |
| 只渲染表层提速 | **已实现** | voxel_renderer 的 greedy meshing 本来就只输出边界面 |

### 4.2 升级路径(若触发条件出现)

若未来核心格式确实需要每体素置信度(触发:跨 run 的增量融合要求 .vxw 本身携带置信度,而非 sidecar):
1. 优先评估复用现有 `state` 字节的空闲位(不破字节布局);
2. 仍不够才走 format_version 1.1 扩记录,按 §8.2 规矩先写迁移说明。
